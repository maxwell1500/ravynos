# jansson — provenance of the vendored JSON library

Vendored so that `BSD/lib/libjansson` has the sources its Makefile names, the
same way `contrib/sqlite3` feeds `BSD/lib/libsqlite3`. Without these files the
library cannot be built at all, and `BSD/bin/launchctl` — which does
`#include <jansson.h>` at `launchctl.c:49` and references the jansson API 106
times — cannot compile.

### Why GitHub and not digip.org

`https://digip.org/jansson/` — the historical publisher URL — now answers
`302 Found` and redirects to `https://github.com/akheron/jansson`. The
`https://digip.org/jansson/releases/` directory still serves files, but its
newest release is **2.13.1**; `jansson-2.14.tar.gz` and later return `404`
there. The publisher's current release channel is therefore the GitHub
releases page, and 2.15.1 is the newest official release it carries.

### Verification

The archive was verified two independent ways, because `gpg` is not installed
on this host:

1. **Homebrew's formula.** `homebrew-core`'s `Formula/j/jansson.rb` names the
   identical URL and the identical sha256
   `0c7114dc0b2d22a670724a1f95922029d7077c19dbf79a584cb8084d2f267f2f`, so the
   bytes match a widely-distributed third-party copy.
2. **The publisher's detached signature.** The `.asc` was fetched from the
   same release and verified with `pgpy` against the signer's public key from
   `keyserver.ubuntu.com`. Result: **signature valid**, signed 2026-07-01 by
   key `D3657D24D058434C`, uid `Petri Lehtinen <petri@digip.org>`.

### Generated by the official `configure` (not hand-written)

`jansson.h` includes `<jansson_config.h>` and the private sources include
`"jansson_private_config.h"`, so both must exist before anything compiles.
They are produced by the release's own `configure`, exactly as upstream builds
them, with the host compiler on this Darwin host:

```
cd jansson-2.15.1 && ./configure --prefix=/usr --disable-shared --enable-static
```

The two outputs were then copied in beside the sources:

| file | bytes | sha256 | provenance |
|---|---|---|---|
| `src/jansson_config.h` | 1,513 | `e73bb56652077335e06d53df5751dc3e4e70aa8d98d0af9869a42f5fdfe5663e` | `src/jansson_config.h.in` + `configure` substitutions |
| `src/jansson_private_config.h` | 5,725 | `d7cd7defb6beac378f4d0dfd018c2b436616f70eb3b68849644d81c0d62de7be` | top-level `jansson_private_config.h.in` + `configure` |

`DTOA_ENABLED` is `1` (jansson's `configure` default), so `src/dtoa.c` is part
of the build. The feature macros (`HAVE_SCHED_H`, `HAVE_GETTIMEOFDAY`,
`HAVE_OPEN`/`CLOSE`/`READ`, `HAVE_UNISTD_H`, …) describe Darwin; ravynOS
supplies every corresponding header and libSystem export, so the same config
is valid for the target. `HAVE_ENDIAN_H` is left undefined by the host
`configure`; ravynOS does ship `endian.h`, but jansson's fallback byte-order
detection is used and is correct.

the plain `_PROVENANCE` file, so this import is also recorded in
`contrib/_PROVENANCE`, with the hashes above carried here.
